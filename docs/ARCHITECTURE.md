# 舉球軌跡分析：架構規劃

## 0. 目標

從練球／比賽錄影中找出每一顆舉球，重建成 3D 軌跡，畫在球場上，並算出教練看得懂的數字（舉到哪一區、多高、飛多久），讓舉球員和教練一起覆盤。

參考：Threads 上的示範影片（使用者提供的螢幕錄影）。畫面左邊是原影片、右邊是把每顆舉球畫成 3D 弧線的球場視圖，用綠／黃／紅標示「好／普通／待改進」，有「標記模式」「側面」「跟球」「只看舉球員＋攻擊手」「全部舉球軌跡」等切換。這個專案做出同樣用途的工具，但介面、程式都自己寫。

## 1. 整體架構：「眼睛」與「大腦」分開

```
                 ┌──────────────── 網頁工具 app/index.html（大腦＋介面）────────────────┐
影片檔 ──┬──────▶│ ① 場地校正 → 相機模型（含廣角變形）                                    │
         │       │ ② 球的位置（手動點，或匯入自動偵測的軌跡 → 用物理切段 → 候選）           │
         │       │ ③ 3D 拋物線擬合（重力已知 → 單一支手機就能算出深度）                   │
         │       │ ④ 舉球指標：起點、終點、最高點、飛行時間、目標區（大砲／欄中／背／後排） │
         │       │ ⑤ 檢視：影片上疊軌跡、底線後／側面／俯視、評等、統計                   │
         │       │ ⑥ 匯出：專案 JSON、訓練用標註                                         │
         │       └──────────────────────────────────────────────────────────────────────┘
         │                      ▲ 候選軌跡 JSON              │ 訓練標註 JSON
         │                      │                            ▼
         └──────▶ detector/（Python，眼睛）：每一格找球 → 串成連續的軌跡
                   ├ 基準版：三格差分＋形狀過濾（不用訓練）
                   └ 進階版：YOLO 用網頁工具標出來的球微調
```

- **網頁工具**做所有幾何計算和介面。單一 HTML、原生 JS，`file://` 直接開，影片只在本機讀，不上傳。
- **Python** 只負責「在每一格畫面找出球的像素位置、串成連續的軌跡」，輸出時間＋像素座標。切段（接球／舉球／扣球）和所有 3D 計算都在網頁工具，兩邊不重複實作：網頁工具有相機模型，可以用真正的物理誤差判斷哪裡被碰到，比在畫面上擬合曲線準。
- 手動標記就是訓練資料：在網頁工具點過的球，匯出後直接拿去訓練 YOLO。所以**先手動標記也能用，標得越多，自動偵測就越準**。

## 2. 座標系統

- 單位：公尺、秒。
- 原點：球網正下方、場地中心的地板。
- `y`：垂直於球網。**近端（靠近攝影機的那一半）是 `y < 0`**，近端底線 `y = -9`，中線 `y = 0`，遠端底線 `y = 9`。
- `x`：沿著球網。**「左／右」一律以「站在近端場地、面向球網」為準**；左邊線 `x = -4.5`，右邊線 `x = 4.5`。
- `z`：往上。網子上緣 `z = 2.43`（男網，可改 2.24），標誌桿高出網子 0.8 m。
- 進攻線在 `y = ±3`。

### 2.1 攻擊方座標（算指標時用）

舉球的指標要從「舉球那一隊」的角度看：

- 舉球起點在近端（`y < 0`）：直接用世界座標。
- 舉球起點在遠端（`y > 0`）：把 `x`、`y` 都變號（等於轉 180°）。

轉完之後，攻擊方的場地一定是 `y < 0`、面向 `+y` 的球網，`x < 0` 是 4 號位（左前）、`x > 0` 是 2 號位（右前）。

## 3. 相機模型

```
世界點 X ──(R, t)──▶ 相機座標 Xc ──(除以深度)──▶ 正規化座標 (x, y)
        ──(廣角變形 k1, k2)──▶ (xd, yd) ──(f, cx, cy)──▶ 像素 (u, v)
```

- 針孔模型：`u = f·xd + cx`、`v = f·yd + cy`；`cx, cy` 固定在畫面中心，像素是正方形。
- 徑向變形（Brown 模型）：`xd = x·(1 + k1·r² + k2·r⁴)`，`r² = x² + y²`。
  - 一般倍率（1x）：`k1 = k2 = 0`。
  - **廣角（0.5x、0.7x）**：一起估 `k1, k2`。0.7x 是超廣角鏡頭再裁切，桶狀變形很明顯，邊線會彎。只用 4 個角做平面轉換的話，邊角會算歪。
- 反變形用牛頓法解半徑；超過變形曲線「折返點」的點視為不可見，不畫。
- 相機存成 `{ f, cx, cy, k1, k2, R(9 個數，列優先), t(3), w, h }`。

## 4. 場地校正

使用者在影片上點**已知位置的點**和**已知直線上的點**，程式解出相機參數。

### 4.1 已知點（14 個，點得到幾個算幾個）

| id | 名稱 | 世界座標 |
|---|---|---|
| nearBackL / nearBackR | 近端底線・左角／右角 | (∓4.5, −9, 0) |
| nearAtkL / nearAtkR | 近端進攻線・左端／右端 | (∓4.5, −3, 0) |
| midL / midR | 中線・左端／右端 | (∓4.5, 0, 0) |
| farAtkL / farAtkR | 遠端進攻線・左端／右端 | (∓4.5, 3, 0) |
| farBackL / farBackR | 遠端底線・左角／右角 | (∓4.5, 9, 0) |
| netTopL / netTopR | 網子上緣・左／右標誌桿處 | (∓4.5, 0, 網高) |
| antTopL / antTopR | 左／右標誌桿頂端 | (∓4.5, 0, 網高＋0.8) |

### 4.2 已知直線（每條可以點很多點；廣角時用來把線「拉直」）

| id | 名稱 | 固定的座標 |
|---|---|---|
| sideL / sideR | 左／右邊線 | x = ∓4.5、z = 0 |
| nearBack / farBack | 近端／遠端底線 | y = ∓9、z = 0 |
| nearAtk / farAtk | 近端／遠端進攻線 | y = ∓3、z = 0 |
| mid | 中線 | y = 0、z = 0 |
| netTop | 網子上緣 | y = 0、z = 網高 |
| antL / antR | 左／右標誌桿 | x = ∓4.5、y = 0 |

直線點的誤差：從像素打一條射線，和其中一個固定座標的平面求交點，再把另一個固定座標換成正確值，投影回畫面，算與點擊位置的像素距離。

### 4.3 解法

1. **初值**：至少 4 個地板點 → 平面轉換矩陣（DLT，Hartley 正規化）→ 用「兩軸垂直、等長」的條件估焦距 `f`，再加上幾個常見焦距（0.4w～1.4w）一起當候選 → 從平面轉換拆出 `R, t`。
2. **精修**：Levenberg–Marquardt 最小化所有像素誤差，參數是 `f`、（廣角時）`k1, k2`、旋轉的小角度修正 3 個、`t` 3 個。
3. 每個候選初值都跑一次，取誤差最小的。
4. 顯示 RMS 像素誤差，把整個球場、球網、標誌桿依相機模型（含變形）疊回影片，使用者用眼睛確認線有沒有貼齊；不貼就拖動點再算。

最少需要：4 個地板點＋2 個不在地板上的點（網子上緣或標誌桿）。只有地板點也能算，但高度會比較不準，畫面會提醒。

## 5. 3D 拋物線擬合

一顆舉球從離手到被攻擊手碰到，在空中只受重力（空氣阻力先忽略）：

```
X(τ) = p0 + v0·τ + ½·g·τ²，g = (0, 0, −9.81)，τ = t − t0
```

- 觀測：一串 `(t, u, v)`。`t` 是影片時間乘上「影片 1 秒 = 實際幾秒」（慢動作才需要改，預設 1）。
- 未知數 6 個：`p0`、`v0`。重力的大小已知，所以「飛多久」決定了「多遠」，單一支攝影機就能算出深度。
- **線性初值**：把像素反變形成正規化座標 `(x, y)`，投影式 `x·(r3·X + t3) = r1·X + t1` 對 `p0, v0` 是線性的，每個觀測給 2 條方程式，用最小平方法解。
- **精修**：Levenberg–Marquardt 最小化像素誤差。
- **離群點**：6 點以上時，誤差超過 `max(4 px, 3 × 中位數)` 的點逐一剔除重算，最多剔除 1/4。
- 至少 4 點；建議 6～12 點，平均分布在整段飛行。

## 6. 舉球指標（攻擊方座標）

| 指標 | 算法 |
|---|---|
| 起點、終點 | 第一個、最後一個標記時間的 3D 位置 |
| 飛行時間 | 終點時間 − 起點時間 |
| 最高點 | `vz = 0` 的時間落在飛行區間內就用它，否則取起點、終點較高者 |
| 高出網子 | 最高點 − 網高 |
| 方向 | 終點 x < 起點 x：往 4 號位；反之：往 2 號位 |
| 終點離網 | −終點 y |
| 目標區 | 終點離網 > 3 m：**後排**；否則終點 x < −1.5：**大砲**（4 號位）、x > 1.5：**背**（2 號位）、其餘：**欄中**（3 號位） |
| 離手速度 | 起點速度的大小 |

目標區用的四個字跟 `ntuche-volley` 的配球計數（大砲／欄中／背）一致，之後可以直接對照。

評等「好／普通／待改進」由教練手動按，程式不自動打分數。

## 7. 資料格式（專案檔 JSON）

```js
Project = {
  schema: 1, app: "setter-track",
  video: { name, size, duration, w, h, fps: 60, realPerVideo: 1 },
  settings: { netHeight: 2.43, ourSide: "near" | "far", wide: false },
  calib: {
    points: { [landmarkId]: { u, v } },      // 4.1
    lines:  { [lineId]: [ { u, v }, … ] },   // 4.2
    cam: Camera | null, rms: number | null
  },
  sets: [ Set, … ],
  candidates: [ { id, points: [ { t, u, v } ], dismissed: [ [t0, t1], … ] } ]   // 自動偵測匯入的軌跡；略過的時間段
}

Set = { id: "s_…", marks: [ { t, u, v } ], grade: null | "good" | "ok" | "bad",
        note: "", src: "manual" | "auto", created }
```

- `t` 存影片時間（秒），不乘倍率；擬合時才乘。逐格跳轉停在「這一格的中間」`(n + 0.5) / fps`，`detect.py` 也用同樣的時間，換回格數一律 `floor(t × fps)`。
- 擬合結果、指標都**不存**，每次從 `marks` 和 `cam` 重算。改了校正，所有軌跡自動跟著更新。
- 存檔：自動存在本機（localStorage，依影片檔名＋大小分開），也可以下載／開啟 JSON。

### 7.1 偵測結果（Python → 網頁）

```js
{ app: "setter-track-detector", version: 1,
  video: { name, w, h, fps, frames },
  tracks: [ { id, points: [ { t, u, v } ] } ] }    // 每條是連續追到的球，還沒切段
```

匯入後（要先校正）：

1. **切段**（`splitBallistic`）：從每條軌跡開頭取 6 點，用相機模型擬合 3D 拋物線；逐點延伸，重投影誤差超過 `max(2.5, 0.25% × 畫面寬)` px 就是球被碰到了，切開。單一個雜點（後面兩點還接得上）跳過不切。
2. 每段做完整擬合，符合「像舉球」條件的列為候選：起點高度 1.6～4 m、起點離網 3.5 m 內、飛行 0.3～2.5 秒、終點在攻擊方場地離網 4.5 m 內、最高點不低於網子 0.5 m 以上、擬合誤差在門檻內。
3. 已經是舉球（手動標記或已加入）的時間段、被略過的時間段不再列出。
4. 使用者按「加入」或「全部加入像舉球的」才變成正式的舉球。

短軌跡看不出深度（1/10 秒內重力只讓球掉幾公分），線性初值會「縮到相機上」；所以線性初值的每條方程式除以估計深度，再加一個很弱的先驗（起點靠近第一點射線上 2.5 m 高的位置，偏 1 m 約等於 0.3 px 的代價）。軌跡夠長時先驗幾乎沒有影響。

## 8. 網頁工具畫面

兩欄：左邊是影片（上面疊一層畫布），右邊是目前模式的面板。窄螢幕上下排列。

- **頂部**：開啟影片、開啟／下載專案、匯入偵測結果、匯出訓練標註、設定（fps、影片 1 秒 = 實際幾秒、網高、我方在近端或遠端、廣角鏡頭）。
- **影片控制**：播放／暫停、±1 格、±1 秒、0.25×／0.5×／1×、時間軸。快捷鍵：空白鍵、←／→（1 格）、Shift＋←／→（1 秒）。
- **① 場地校正**：俯視球場示意圖（點選要標的點或線，選到的會亮起來）；在影片上點擊放點、拖動修正；放大鏡；「計算」後疊回整個球場與 RMS 誤差。
- **② 標記舉球**：「新增一顆舉球」→ 在影片上點球的位置，每點一下自動前進 N 格（預設 3）；4 點以後即時擬合並把弧線疊在影片上；Backspace 復原、Enter 完成、Esc 取消。
- **③ 檢視**：3D 視圖（底線後可拖曳旋轉、側面、俯視），全部或只看選取的那顆，球場線／球網／標籤開關；清單顯示每顆的時間、哪一隊、目標區、最高點、飛行時間、評等按鈕、註解；下方是統計（各目標區的次數、平均最高點、平均飛行時間、評等分布）。

## 9. Python 偵測（detector/）

### 9.1 基準版 `detect.py`（不用訓練）

1. 三格差分：`|f(t) − f(t−k)| ∧ |f(t+k) − f(t)|`（k ≈ 1/20 秒，60fps 是 3 格，讓球移動超過自己的直徑），留下「這一格才出現在這裡」的東西（快速移動的小物體），慢慢走動的人會被消掉大半。
2. 門檻、連通區域；用面積、長寬比、填滿率過濾成「像球」的候選；用背景模型（MOG2）的前景把中心修正到整顆球的中心；`--color yellow` 讓黃色的球加分。
3. 追蹤：用最近幾點做二次預測，在預測位置附近找候選，最多容許連續 4 格沒找到。
4. 只留下像球的軌跡：至少 8 點、涵蓋的格數裡 70% 以上有找到、範圍超過畫面寬 2%、淨移動速度夠快（人身上的雜訊通常斷斷續續、在原地抖動）。
5. 輸出 7.1 的 JSON。切段在網頁工具做（7.1）。

### 9.2 進階版（要訓練）

1. 在網頁工具標記 30～50 顆舉球（大約 300～500 個球的位置）。
2. 匯出訓練標註 → `make_dataset.py` 從影片抽出那些格，在球附近切 640×640 的小圖（不縮放，球在小圖裡的位置隨機），寫成 YOLO 格式（框的大小用 `r`）。訓練／驗證以「一段舉球」為單位分，避免相鄰幾格同時出現在兩邊。
3. `train.py` 用 ultralytics YOLO 微調（筆電 CPU 很慢，建議 Colab GPU）。
4. `detect.py --model best.pt` 改用 YOLO 找候選（用原解析度偵測，球的大小跟訓練時一致），追蹤不變。

## 11. 這版不做

- 自動評等（好／普通／待改進）。
- 自動辨識是誰舉的、誰攻擊的（可以之後從 ntuche-volley 的輪轉資料帶入）。
- 空氣阻力、旋轉。
- 多台攝影機。
- 直接讀 YouTube／Threads 網址（瀏覽器讀不了別的網站的影片畫面）；要先下載成檔案。

## 12. 容易誤解的地方

1. **左右以「站在近端場地、面向球網」為準**，不是畫面的左右。攝影機在側邊時特別容易點反；示意圖會標出每個點的位置。
2. **近端 = 靠近攝影機的那一半**，跟哪一隊是「我方」無關；我方在哪一邊另外設定。
3. **fps 只影響「下一格」按鈕跳多少**，物理計算用的是影片時間戳，fps 設錯不會讓軌跡算錯。
4. **慢動作影片一定要設「影片 1 秒 = 實際幾秒」**（例如 240fps 慢動作用 30fps 播：0.125），否則重力對不上，軌跡會錯得很離譜。
5. **錄影中途不能改倍率、不能移動手機**；改了就要重新校正。加強防手震、運動模式要關，它們每一格都在偷偷裁切。
6. **0.7x／0.5x 一定要勾「廣角鏡頭」**，並盡量多點直線上的點（尤其靠畫面邊緣的邊線、底線）。
7. 標記時點的是**球的中心**，不是影子、不是球的下緣。
8. 舉球的「起點」是第一個標記點、「終點」是最後一個標記點：從舉球員手離開後第一格點到攻擊手碰到前最後一格。
9. **時間一律是「這一格的中間」**`(n + 0.5) / fps`（網頁逐格跳轉、`detect.py` 輸出都一樣）。換回格數用 `floor(t × fps)`，不要四捨五入。
10. **Python 不切段**：`detect.py` 輸出的是連續追到的整條球，接球、舉球、扣球會連在一起；切段要有相機模型，在網頁工具做。
