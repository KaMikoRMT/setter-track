## P4：自動偵測＋網頁切段

**完成**

- `detector/detect.py`：三格差分（k ≈ 1/20 秒）找快速移動的小物體 → 面積、長寬比、填滿率過濾 → MOG2 前景修正中心 → 二次預測追蹤（容許漏 4 格）→ 只留下像球的軌跡（夠長、夠連續、夠大、移動夠快）→ 輸出連續軌跡 JSON。選項：`--start/--end`、`--color yellow`、`--debug` 標註影片、`--model`（YOLO，P5）。
- 網頁工具：`splitBallistic` 用相機模型逐點延伸 3D 拋物線，重投影誤差超過門檻就切開（雜點跳過）；`deriveCandidates` 切段 → 擬合 → 像不像舉球 → 已是舉球或略過的時間段不列出。「② 標記舉球」列出像舉球的段（可展開不像的）、看／加入／略過、全部加入、清掉偵測結果；結果有快取，不會每次重畫都重算。
- `node tests/selftest.mjs`：20 項全過（新增：一條連續的球切成接球／舉球／扣球、雜點跳過；候選只有舉球那段像舉球、加入或略過後不再列出）。
- `python3 detector/tests/test_synthetic.py`：合成影片找回 95.6% 的球（478/500 格），位置誤差中位數 1.24 px，16 條軌跡。
- `node tests/ui-check.mjs`：匯入偵測結果 → 全部加入 → 手動 1 顆＋自動 2 顆剛好是三顆舉球（含一顆遠端對方的），目標區與隊伍都對，沒有誤判。

**判斷紀錄（P4）**

- 2026-11-04・P4・**切段移到網頁工具**（規格原本寫在 Python）：網頁工具有相機模型，可以用真正的 3D 物理誤差判斷哪裡被碰到；Python 在畫面上擬合二次曲線會被透視與廣角變形干擾。也符合「幾何只在一個地方」的規則。偵測結果格式從 `segments` 改成 `tracks`。
- 2026-11-04・P4・**短軌跡的線性初值會縮到相機上**（實測 6 點時起點算到相機位置）：每條方程式除以估計深度，再加很弱的位置先驗。測試「切段」一開始就是因為這個失敗。
- 2026-11-04・P4・**時間一律是格的中間** `(n + 0.5) / fps`：`detect.py` 原本輸出 `n / fps` 並四捨五入到 5 位小數，換回格數時有些格會錯一格，做訓練資料時抓到這個問題。
- 2026-11-04・P4・**候選和已有的舉球重疊就不列出**，不另外記「已加入」：手動標過的舉球不會再出現一次。
- 2026-11-04・P4・**軌跡過濾門檻**（連續 70%、範圍 2% 畫面寬、淨速度 1.2 px／格）是看合成影片的假軌跡統計定的：假軌跡多半斷斷續續、在原地抖；真的球幾乎每格都有。真實影片可能要調。
